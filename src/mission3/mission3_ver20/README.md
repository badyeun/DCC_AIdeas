# Mission 3 ver20

## One candidate: KLUE-RoBERTa-large with partial fine-tuning

`large_partial_ce` starts from `klue/roberta-large`, pinned to revision `28d911204e9022eda172571ca8cc61eaffd942f7`. The official model has 24 encoder layers and hidden size 1024. Embeddings and the first 16 encoder layers are frozen; the last 8 layers and nine two-class symptom heads train. The base classification and weighted cross-entropy recipe follow ver15. There is no GCE, utterance-evidence branch, label attention, contrastive loss, threshold search, or post-hoc score adjustment.

The objective is to improve shared Korean context representation while limiting training cost. Eight trainable layers are an experimental budget choice, not an established optimum. Large-model F1 and complete GPU runtime have not been measured locally, and improvement is not guaranteed. Sources: [official model](https://huggingface.co/klue/roberta-large), [pinned revision](https://huggingface.co/klue/roberta-large/commit/28d911204e9022eda172571ca8cc61eaffd942f7), [official configuration](https://huggingface.co/klue/roberta-large/blob/28d911204e9022eda172571ca8cc61eaffd942f7/config.json).

Inputs remain only `utterances[].text`. All supplied utterances, overflow windows, samples, and original labels remain. Windows use maximum length 512 with overlap 64. Batch size 4 and gradient accumulation 4 give 16 conversations per full optimizer step. Encoder windows are processed in chunks of 4. Encoder learning rate is 2e-5, head learning rate 1e-4, and both the maximum training length and scheduler horizon are three epochs. Positive weights in `[고열, 구토, 두통, 복통, 어지러움, 열상, 오심, 전신쇠약, 호흡곤란]` order are `[1.4, 1.8, 2.0, 1.2, 1.3, 1.0, 3.0, 1.5, 1.3]`. Predictions are raw two-class argmax decisions for each symptom.

## Evaluation and the embedded Training reference

The existing grouped Training split uses seed 42 and holdout size 0.2. Actual indices are saved to `training_split.npz`. Epoch selection uses only Training holdout results: prefer epochs whose Macro F1 and nausea F1 both exceed the verified ver19 reference, then choose the highest Macro F1 among them. If no epoch passes both conditions, retain the highest-Macro-F1 epoch as a diagnostic result and skip full refitting. This prevents a later high-Macro but lower-nausea epoch from discarding an earlier jointly improved epoch. There is one newly trained candidate and no baseline retraining.

`training_reference.json` embeds prior Training-holdout binary predictions and provenance hashes, without patient text or sample IDs. `reference.py` verifies the current Training data, labels, and split before comparing to the embedded reference. `training_reference_comparison.json` reports historical metrics, per-label changes, and nausea error transitions. Its primary reference is ver19. Joint improvement requires both overall Macro F1 and nausea F1 to increase. Failure of either condition skips full refitting to save time: the completed fit-only model and experimental predictions remain, with status `complete_not_improved` and `refit_skipped_reason: training_reference_not_jointly_improved`. They are not presented as a newly recommended submission. This gate does not load an old trained model or replace the new experiment with an older checkpoint. Previous outputs remain separate.

This reused holdout is exploratory and is not an untouched independent test. Reference information is not a model input, loss term, sampler, threshold, or label correction. Official Validation is evaluated once after final model selection and is not used for training, epoch selection, or reference comparison.
