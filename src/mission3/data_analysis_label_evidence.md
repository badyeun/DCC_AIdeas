# Mission 3 데이터 분석 — 왜 오심·두통이 안 나오는가

- 분석일: 2026-09-19
- 대상: 서울 Training 29,200개 + Validation 3,640개 라벨 JSON **전체**
- 산출물: `analysis/label_evidence_report.json`, `analysis/samples_for_human_review.txt`

---

## 결론 먼저

**모델 문제가 아니라 라벨 문제입니다.**

증상별 모델 점수는 "그 증상이 전사 텍스트에서 실제로 읽히느냐"만 따라갑니다. 둘의 상관계수가 **0.884**입니다.

오심은 **정답에 오심이 붙은 통화의 84%에서 전사에 메스꺼움 관련 표현이 단 한 번도 안 나옵니다.** 전사만 읽는 모델이 원리적으로 맞힐 수 없는 라벨입니다.

그리고 Training 통화의 **32.5%(9,497개)는 자기가 가진 어떤 증상 라벨의 근거도 전사에 없습니다.** 이 통화들의 평균 길이는 451자로, 전체 평균 465자와 거의 같습니다. 통화가 짧아서가 아니라, **증상 얘기를 안 하는 통화**입니다.

---

## 1. 전사 근거율 vs 모델 점수

각 증상마다 넉넉한 한국어 표현 목록을 만들고, 그 증상이 정답에 있는 통화에서 표현이 실제로 등장하는 비율을 셌습니다.

**Training 29,200개**

| 증상 | 정답 수 | 전사에 근거 있음 | **근거율** | 근거 없음 | 모델 F1 |
|---|---:|---:|---:|---:|---:|
| 호흡곤란 | 3,927 | 2,853 | 72.7% | 1,074 | 0.679 |
| 열상 | 3,465 | 2,467 | 71.2% | 998 | **0.894** |
| 복통 | 6,771 | 4,167 | 61.5% | 2,604 | 0.825 |
| 고열 | 5,186 | 3,119 | 60.1% | 2,067 | 0.697 |
| 어지러움 | 6,334 | 3,608 | 57.0% | 2,726 | 0.659 |
| 구토 | 4,463 | 1,957 | 43.9% | 2,506 | 0.609 |
| 전신쇠약 | 5,310 | 2,278 | 42.9% | 3,032 | 0.593 |
| 두통 | 2,905 | 1,096 | 37.7% | 1,809 | 0.550 |
| **오심** | 3,341 | **532** | **15.9%** | **2,809** | **0.403** |

Validation 3,640개도 같은 순서입니다 (오심 17.7%, 두통 40.4%, 열상 68.7%).

**근거율과 모델 F1의 상관계수 = 0.884.**

순서가 거의 그대로 뒤집히지 않고 이어집니다. 지금까지 ver3→ver8에서 모델 구조·크기·손실함수를 아무리 바꿔도 점수가 안 움직인 이유가 여기 있습니다. **모델이 못 배운 게 아니라 텍스트에 정보가 없습니다.**

> 한 가지 예외는 호흡곤란입니다. 근거율은 가장 높은데 F1은 중간(0.679)입니다. 접수요원이 거의 모든 통화에서 "숨 쉬는 건 어때요?"를 묻기 때문에 제 키워드가 과하게 잡혔습니다. 측정 한계이지 실제 신호가 아닙니다.

## 2. 오심 — 라벨이 통화에 없습니다

### 실제 전사

```
정답 = ['구토', '복통', '오심']
전사 = "딸내미가 복통을 일으켜가지고 지금 참을 수가 없어요" … "배가 아픈 거죠, 딸이?"
     → 토한다는 말도, 메스껍다는 말도 전사에 아예 없음
```

```
정답 = ['오심']          (원본 라벨: 기타, 오심)
전사 = "지금 수면제를 너무 많이 먹어 가지고" … "한 통 먹었어요"
     → 약물 과다복용 신고. 메스꺼움 언급 없음
```

```
정답 = ['어지러움', '오심']
전사 = "막 어지럽고, 막 어지럽고 토하고 이래갖고요"
     → 토한다고 두 번 말했는데 구토는 라벨에 없고 오심만 있음
```

### 무엇이 벌어지고 있나

오심 라벨 3,341건 중 2,809건(84%)에 전사 근거가 없습니다. 그런데 이 2,809건이 특별한 집단인 것도 아닙니다. 근거 있는 532건과 비교하면:

| | 근거 있는 532건 | 근거 없는 2,809건 |
|---|---|---|
| 신고 유형 | 질병(중증 외) 91% | 질병(중증 외) 86% |
| 같이 붙는 라벨 | 어지러움, 구토, 복통 | 어지러움, 구토, 복통 |
| 전사에 구토 표현 | 25.9% | 23.5% |

**두 집단이 구별되지 않습니다.** 오심은 특정 상황에서만 기록에서 오는 게 아니라, 그냥 전반적으로 전사와 무관하게 붙습니다.

오심과 함께 붙는 9개 외 라벨은 설사(331), 기타(327), 기타통증(227), 실신(107) 순입니다. 위장관 증상 묶음의 일부로 다뤄지는 것으로 보입니다.

### 그래서 모델이 하는 일

모델의 오심 재현율은 0.543입니다. **근거율 17.7%보다 훨씬 높습니다.** 즉 모델은 전사에서 오심을 읽어내는 게 아니라, **"토했다"·"어지럽다"·"복통" 같은 주변 단서로 오심을 추측**하고 있습니다.

그래서 정밀도가 0.320입니다. 추측이니까요. Validation에서 오심을 727번 예측하는데 정답은 429개, **+298개 과잉**입니다. 9개 중 압도적 1위입니다.

모델은 주어진 정보로 할 수 있는 걸 하고 있습니다. 더 큰 모델을 써도 없는 정보가 생기지는 않습니다.

## 3. 구토 — 같은 전사에 라벨이 4가지로 갈립니다

전사에 "토했다 / 게웠다 / 구토" 같은 표현이 **분명히 있는** 통화 2,879건의 라벨 분포입니다.

| 라벨 결과 | 건수 | 비율 |
|---|---:|---:|
| 구토만 | 1,409 | 48.9% |
| 구토 + 오심 | 548 | 19.0% |
| **오심만 (구토 없음)** | **249** | **8.6%** |
| **둘 다 없음** | **673** | **23.4%** |

**똑같이 "토했어요"라고 말한 통화인데 라벨이 네 갈래로 갈립니다.** 절반만 구토로 붙고, 32%는 구토가 아예 안 붙습니다.

이것이 관측된 실패 양상을 정확히 설명합니다.

- **구토 재현율이 0.542로 낮은 이유** — "토했다"고 말해도 3번 중 1번은 구토 라벨이 없습니다. 모델은 "토했다 → 구토"를 확신할 수 없게 학습됩니다.
- **오심이 과잉 예측되는 이유** — "토했다"에 오심이 붙는 경우가 27.6%(548+249 중)나 되니, 모델은 구토 표현만 봐도 오심을 같이 꺼냅니다.

전체로 보면 구토만 3,172 / 오심만 2,050 / 둘 다 1,291입니다. P(오심|구토)=28.9%, P(구토|오심)=38.6%로, **두 라벨이 겹치지만 일관된 규칙은 없습니다.**

## 4. 두통 — 원인이 두 가지입니다

근거율 37.7%로 아래에서 두 번째입니다. 전사를 보면 두 종류가 섞여 있습니다.

**(a) 머리 외상이 두통으로 기록됨**

```
정답 = ['두통', '열상']   (원본: 두통, 기타통증, 열상, 찰과상, 타박상)
전사 = "소주병으로 맞은 분이 있어가지고" … "머리에 피 많이 나요?"
     → 머리를 다친 것이지, 두통을 호소한 게 아님
```

```
정답 = ['두통']          (원본: 두통, 요통, 기타, 기침)
전사 = "의자 위에서 떨어졌어요" … "어디가 아프신 거예요?" "머리가, 머리가."
```

실제로 두통은 9개 중 유일하게 **'부상' 유형에 몰리는** 증상입니다(12.4% vs 전체 9.9%, 1.25배). 두통 라벨의 상당수가 "머리가 아프다"가 아니라 "머리를 다쳤다"입니다.

**(b) 전사에 아무 증상 정보가 없음**

```
정답 = ['고열', '두통']
전사 = "네, 여보세요?" / "119입니다" / "저희 구급차 가고 있구요" / "연빌리지가 석촌동 맞아요?"
     → 전사 전체가 주소 확인. 증상 얘기가 한 마디도 없음
```

이런 통화는 어떤 모델도 맞힐 수 없습니다.

## 5. 그 밖에 나온 것

**전신쇠약 (F1 0.593, 근거율 42.9%)** — "기운이 없다/힘이 없다/축 처진다" 계열 표현이 원래 모호하고, 근거 없는 라벨이 3,032건입니다. 오심·두통과 같은 부류지만 정도가 덜합니다.

**열상과 호흡곤란만 신고 유형과 강하게 붙습니다** — 열상은 '부상'에 6.35배, 호흡곤란은 '질병(중증)'에 4.81배 집중됩니다. 나머지 7개는 1.1~1.4배로 거의 안 갈립니다. 열상의 F1이 0.894로 가장 높은 것과 무관하지 않습니다.

**동일 전사가 다른 라벨을 갖는 사례는 0건입니다** — 중복 전사 자체가 없어서, 이 방향으로 라벨 노이즈를 직접 증명하는 건 불가능합니다.

**증상 0개인 통화가 하나도 없습니다** — Training 29,200개, Validation 3,640개 **전부** 9개 중 최소 1개를 갖고 있습니다. 라벨 개수 분포는 1개 19,560 / 2개 7,137 / 3개 2,161 / 4개 325 / 5개 17입니다.

> 팀 문서 `docs/예선대비_핵심정리.md`에는 "0개 라벨 샘플도 존재 → 아무 증상도 예측하지 않는 출력을 허용해야 함"이라고 적혀 있습니다. **실제 서울 구급 데이터에서는 그런 통화가 없습니다.** 출제 PDF가 "0~9개 가능"이라고 한 것과 실제 데이터 분포는 다릅니다.

## 6. 지금 바로 할 수 있는 것

저장된 ver4 예측 CSV와 실제 정답으로 계산한 수치입니다. 현재 Macro F1 = 0.656649.

### (1) 최소 1개는 출력하게 하기

현재 모델은 108개 통화(3.0%)에 아무것도 예측하지 않습니다. 그런데 그 108개 전부 실제로는 증상을 갖고 있습니다(총 132개).

| 시나리오 | Macro F1 | 변화 |
|---|---:|---:|
| 현재 | 0.656649 | — |
| 채운 게 30% 맞을 때 | 0.660619 | **+0.0040** |
| 채운 게 50% 맞을 때 | 0.663088 | **+0.0064** |
| 전부 맞을 때 (상한) | 0.669887 | +0.0132 |

**GPU 없이, 추론 코드 몇 줄로 끝납니다.** 확률이 가장 높은 증상 1개를 강제 출력하면 됩니다. 어떤 증상을 고를지는 저장된 보정 데이터(`ver4/calibration_predictions.npz`)로 CPU에서 미리 검증할 수 있습니다.

다만 **Validation으로 이 규칙을 튜닝하면 규정 위반**입니다. 반드시 Training 보정 데이터에서 정하고 Validation은 마지막 확인만 하세요.

### (2) 오심 오답 줄이기

| 시나리오 | Macro F1 | 변화 |
|---|---:|---:|
| 오심 오답의 40% 제거 | 0.665850 | **+0.0092** |
| 오심 오답의 60% 제거 | 0.672065 | +0.0154 |
| 오심 오답 전부 제거 (상한) | 0.690073 | +0.0334 |

상한 +0.0334는 ver3→ver4의 개선폭(+0.031)보다 큽니다. 다만 "오답만 골라서 지운다"는 건 정답을 봐야 가능한 일이라 실제로는 불가능합니다. **오심의 확률 추정 자체를 개선해야** 근접할 수 있습니다.

### (3) 오심·구토를 하나로 묶어 다루기

오심과 구토는 라벨 단계에서 이미 섞여 있습니다. "토했다 계열 표현 → 구토와 오심 중 무엇이 붙을지"를 별도로 학습시키는 2단계 구조가 후보입니다.

**단, 이건 규정 확인이 필요합니다.** 9개 증상을 각각 예측하라는 조건에 어긋나지 않는지 봐야 합니다. 두 증상의 출력을 합치는 게 아니라 내부 구조만 바꾸는 것이라면 문제없을 가능성이 높지만, 확인하고 진행하세요.

### (4) 텍스트 정규화 — 아직 한 번도 안 했습니다

ver4~ver8 모두 발화 text를 그대로 이어 붙이기만 합니다. 교안이 Mission 3 대비로 권장한 구어체·오탈자 정규화와 동의어 통합을 시도한 적이 없습니다. **모든 샘플에 동일하게 적용하면 규정상 허용됩니다.**

이번 분석에서 실제로 확인된 표기 흔들림입니다.

- 메스껍다 / 매스껍다 / 메슥거리다 / 울렁거리다 / 느글거리다 / 니글거리다
- 토할 것 같다 / 토할 거 같다 / 토할라 그런다 / 오바이트 / 게웠다
- 체했다 / 급체 / 속이 안 좋다 / 속이 불편하다

제가 처음에 `토할 것 같` 만 넣고 `토할 거 같`을 빠뜨려서 분석을 다시 돌려야 했습니다. 실제 통화에서는 "거"가 훨씬 흔합니다. 모델도 같은 문제를 겪고 있을 수 있습니다.

## 7. 이 분석의 한계

- **근거율은 키워드 일치로 잰 근사치입니다.** 놓친 표현도 있고("머리가 지끈거려" 같은 변형), 과하게 잡힌 것도 있습니다(호흡곤란). 절대값을 그대로 믿으면 안 됩니다.
- 다만 **9개 증상에 같은 방식을 적용했으므로 증상 간 비교는 유효**합니다. 상관계수 0.884는 이 비교에서 나온 값입니다.
- **"전사에 근거가 없다"가 곧 "라벨이 틀렸다"는 뜻은 아닙니다.** 환자에게 실제로 오심이 있었는데 통화에서 말을 안 했을 수 있습니다. 라벨은 맞고 **전사에 정보가 없는 것**입니다. 결과는 같습니다 — 모델이 맞힐 수 없습니다.
- 모델을 재학습하거나 재추론하지 않았습니다. 저장된 ver4 예측 CSV를 사용했습니다.

## 8. 멘토 회의에 가져갈 한 줄

> 증상별 모델 F1은 "그 증상이 전사에서 읽히는 비율"과 상관계수 0.884로 붙습니다. 오심은 정답의 84%가 전사에 근거가 없고, 전사에 "토했다"가 있는 2,879건조차 라벨이 네 갈래(구토만 49% / 둘다 19% / 오심만 9% / 둘다없음 23%)로 갈립니다. 이 상황에서 모델을 더 키우는 게 의미가 있을까요, 아니면 남은 시간을 후처리와 오심·구토 구조에 쓰는 게 나을까요?
