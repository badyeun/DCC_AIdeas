## 0. 한눈에 보기

**과제**: 전화대화 음성 및 전사 데이터를 이용한 응급상황 인식
**데이터**: AI-hub "위급상황 음성/음향(고도화) — 119 지능형 신고접수 음성 인식 데이터"
**최종 평가**: Mission 1·2·3의 **순위를 합산** → 세 미션 모두 균등하게 중요. 한 미션 몰빵 전략은 불리.

| 미션 | 입력 | 출력 | 지표 | 성격 |
|---|---|---|---|---|
| **M1** | 음성 (원천데이터) | 성별 남/여 | Accuracy | 오디오 이진 분류 |
| **M2** | 한 사람의 한 발화 조각 | 신고자(1)/119대원(0) | Accuracy | 오디오 이진 분류 |
| **M3** | 신고자·대원 대화 텍스트 | 증상 0~9개 | **Macro F1** | 텍스트 **멀티라벨** 분류 |

**제시된 도구 후보 (문제p5)**: KoBERT, MFCC, Mel-spectrogram, Wav2Vec2, AST, RandomForest, ResNet
→ **전부 교안에 나온 개념들이다.** 7·8차시(오디오)와 6차시(NLP)가 예선의 핵심 교재.

## 1. 규칙 — 어기면 점수가 아니라 자격 문제

| 규칙 (문제p5) | 교안에서의 근거 |
|---|---|
| AI-hub 제공 데이터만 사용, 외부 데이터 금지 | — |
| 각 미션이 **지정한 입력·출력만** 사용 (미지정 라벨 입력 금지) | — |
| 오픈소스 pre-trained 허용, **상용 AI API(GPT-4o, Google Vision) 금지** | Wav2Vec2/AST fine-tuning은 허용 범위 (p182–183) |
| **Training set은 서울 데이터만** | — |
| **Validation 폴더 데이터는 학습에 사용 금지** | 데이터 누수 금지 (p6, p151, p157) |
| 샘플마다 label에 따라 다른 전처리 금지 | 정답을 보고 전처리하면 누수 |
| 평가 데이터에서만 유리한 특별 전처리 금지 | Val/Test는 `transform()`만 (p6) |

> **교안이 반복해서 강조한 한 줄**: Train으로만 `fit()`, Val/Test는 `transform()`만. **데이터 누수(Leakage) 절대 금지** (p6 전처리 황금 원칙, p151 TF-IDF, p157 미니퀴즈 정답, p190 증강은 Training에만)

## 2. Mission 1 — 신고자 성별 분류

### 요구사항 (문제p7)
- 입력: 음성 원천데이터
- 라벨링데이터는 **학습·추론 모두 `startAt`, `endAt`, `Speaker`만** 사용 가능
- 출력: `gender` (남/여) · 지표: **Accuracy**
- 힌트: 일정 길이 입력 모델을 쓰려면 짧은 음성은 **padding**, 긴 음성은 적절한 stride의 **sliding window**

### 교안 대응 (7차시 p166–p168)
문제의 힌트가 교안 p166~168을 그대로 가리킨다.
- `Sample 수 = Sampling rate × Duration` (p164) — 16kHz 기준으로 목표 길이를 sample 수로 환산
- **Padding**: 짧은 오디오를 겹치지 않는 값으로 늘림
- **Crop**: 긴 오디오에서 일부만 선택 — **중요한 소리를 잘라낼 위험** (p167)
- **Sliding window**: 긴 오디오를 일정 길이 여러 구간으로 분할 (p168) → 구간별 예측 후 **다수결/평균으로 파일 단위 집계**

### 권장 파이프라인
```
wav → 16kHz 리샘플 → Mono 변환 → 고정 길이(padding/sliding window)
   → Log-Mel spectrogram (n_mels 64~128)
   → ResNet(2D 이미지 취급) 또는 AST fine-tuning
   → 남/여 이진 분류
```
- **Baseline 먼저** (p156 원칙): MFCC 통계량(평균·표준편차) + **RandomForest**로 기준 성능 확보 → 이후 딥러닝과 비교
- 성별은 **기본 주파수(F0)** 차이가 크므로 저주파 해상도가 높은 **Mel 척도가 유리** (p173)
- 대안 경로: Wav2Vec2 fine-tuning (Raw waveform 직접 입력, p182)

### 주의할 점
- `Speaker`는 사용 가능하므로 **신고자 발화 구간만 골라내는 데 쓸 수 있다.** 119대원 목소리가 섞이면 성별 라벨과 불일치
- Accuracy가 지표 → **클래스 불균형 확인 필수**. 남/여 비율이 9:1이면 전부 남성 예측해도 90% (p53 그대로의 사례). 학습 시 class weight나 오버샘플링 검토
- Mono/Stereo 채널 수를 반드시 일관화 (p161, p165)

## 3. Mission 2 — 신고자 / 119대원 분류

### 요구사항 (문제p8)
- 입력: **한 사람의 한 발화 조각** (조각 기준은 `startAt`, `endAt`)
- **`startAt`, `endAt` 외 annotation 사용 불가 — text도 사용 불가**
- **발화의 홀짝 등 순서 사용 불가**
- 출력: `speaker` = 신고자(1) / 119대원(0) · 지표: **Accuracy**
- 학습 완료 모델 + 추론 코드 함께 제출

### 이 미션의 함정
"대화니까 홀짝으로 번갈아 나오겠지" — **명시적으로 금지**. 순수하게 **음향 특징만으로** 구분해야 한다.

### 무엇이 신호인가 (교안 p180 Audio 증강 슬라이드의 논리를 뒤집어 활용)
교안 p180은 이렇게 말한다 — *"동일인이 동일 단어를 말해도 녹음 장비, 마이크와의 거리, 배경 소음과 공간의 울림에 따라 Waveform과 Spectrogram은 달라진다."*

M2에서는 이게 **버그가 아니라 피처**다:
- 119 상황실 대원 = 헤드셋 근접 마이크, 실내, 잡음 적음, 발화 안정
- 신고자 = 전화 회선, 야외·현장 소음, 울림, 감정적 발화

즉 **채널 특성 + 배경 소음 + 발화 스타일**이 판별 근거가 된다.

### 권장 파이프라인
```
발화 조각 슬라이싱 (startAt~endAt) → 16kHz Mono → 고정 길이 padding/crop
   → Log-Mel spectrogram
   → CNN(ResNet) 또는 AST
   → 이진 분류
```
- **Baseline**: MFCC 계수 통계 + RandomForest (p156 원칙 — 해석도 쉬움)
- 발화 조각은 M1보다 **짧을 가능성이 크다** → 고정 길이를 짧게 잡고, 너무 짧은 조각은 padding

### 주의할 점
- **증강을 조심해서 써야 한다.** M2의 판별 신호가 곧 "녹음 환경"인데, Noise augmentation을 세게 걸면 **그 신호를 지워버릴 수 있다.** 교안 p181의 원칙 그대로: *"최대한 원본 음성을 방해하지 않는 선에서 Noise 증강 적용"*
- Time/Frequency masking(p180)은 상대적으로 안전한 선택
- 증강은 **Training에만**, Validation/Test는 고정 전처리 (p190)
- 같은 통화에서 나온 조각들이 Train/Val에 섞이면 통화 단위 정보가 새어나갈 수 있음 → **통화(파일) 단위로 split** 권장

## 4. Mission 3 — 환자 증상 인식 (가장 까다로움)

### 요구사항 (문제p9–p10)
- 입력: **전사 텍스트만** (그 외 라벨링데이터 사용 불가)
- 출력: `symptom` — **0개~9개** 가능한 **멀티라벨**
- 9개 클래스만 취급: **고열, 구토, 두통, 복통, 어지러움, 열상, 오심, 전신쇠약, 호흡곤란**
- 9개 외 symptom은 **평가 제외 + 전처리에서 라벨만 제거** (샘플 전체를 지우면 안 됨)
- 예: 정답이 `['두통','복통','찰과상']` → 예측 출력은 `['두통','복통']`
- 지표: **증상 종류별 F1 → 평균 (Macro F1)**

### Macro F1 계산 절차 (문제p10)
1. 통화별 정답/예측
2. 레이블별 이진화 (각 통화에서 그 레이블이 있으면 1)
3. 레이블별 TP/FP/FN 집계
4. Macro 평균 = 클래스별 F1의 단순 평균 — 예: `(0.67 + 0.67 + 0.00)/3 = 0.44`

### 왜 Macro F1이 전략을 바꾸는가
교안 p57이 그대로 답이다. F1은 **조화평균**이라 한쪽이 0에 가까우면 전체가 무너진다 (Recall 1, Precision 0.01 → 산술평균 0.505 vs 조화평균 **0.019**).

Macro는 여기에 더해 **클래스별 F1을 단순 평균**한다.
→ **희귀 증상 1개의 F1이 0이면 전체 점수가 1/9 = 0.111 통째로 날아간다.**
→ 흔한 증상(복통·두통)만 잘 맞히는 모델보다, **모든 클래스를 고르게 맞히는 모델**이 이긴다.
→ 희귀 클래스에 대해 **threshold를 낮춰 Recall을 확보**하는 것이 유리할 수 있다 (p56 Threshold 트레이드오프)

### 권장 파이프라인
```
전사 텍스트 → 한국어 전처리(정규화) → 벡터화 → 9개 이진 분류기(멀티라벨)
```

**Baseline (반드시 먼저 — p156)**
- TF-IDF (word + character n-gram) → 클래스별 Logistic Regression / RandomForest
- 장점: 빠르고, **어떤 단어가 예측에 영향을 줬는지 확인 가능** (p156)
- **TF-IDF의 Vocabulary와 IDF는 반드시 Train에서만 학습** (p151, p157) ← 미니퀴즈로 나올 만큼 강조된 함정

**본 모델**
- **KoBERT** fine-tuning, 출력층 9개 노드 + Sigmoid + BCE Loss (멀티라벨이므로 Softmax 아님)
- 교안 p155: 사전학습 모델은 *"약간의 학습과 일부 데이터만 있어도 다양한 downstream task를 잘 수행"*

### 텍스트 전처리 (p145–p147)
- **전처리를 많이 한다고 무조건 좋은 게 아니다** (p145 명시) — 증상 표현이 지워지지 않게 주의
- 동의어 통합이 핵심: "토했어요/게웠어요/구역질" → 구토·오심 / "숨이 안 쉬어져요/헐떡" → 호흡곤란 / "찢어졌어요/베였어요" → 열상
- **오심 vs 구토**는 의미가 겹쳐 혼동되기 쉬움 → 구분 규칙을 명확히
- 구어체·오탈자·반복문자 정규화 (p147)

### 주의할 점
- **0개 라벨 샘플**도 존재 → 아무 증상도 예측하지 않는 출력을 허용해야 함
- **9개 외 라벨 제거 시 샘플까지 지우지 말 것** (문제p9 명시)
- 출력은 **string type** (문제p9)
- 클래스 불균형이 심할 것으로 예상 → Macro F1 특성상 **희귀 클래스 대응이 승부처**

## 5. 공통 실수 방지 체크리스트

### 데이터 누수 (교안이 가장 반복한 주제)
- [ ] Train/Val split을 **먼저** 하고, 그다음 Vectorizer·Scaler를 `fit` 했는가 (p6, p151, p157)
- [ ] Validation 폴더 데이터를 학습에 쓰지 않았는가 (문제p5)
- [ ] Training set을 **서울 데이터만** 썼는가 (문제p5)
- [ ] 라벨에 따라 다른 전처리를 하지 않았는가 (문제p5)
- [ ] 증강을 **Training에만** 적용했는가 (p190)
- [ ] M2에서 통화 단위로 split 했는가 (같은 통화 조각이 Train/Val에 흩어지지 않게)

### 오디오 전처리 일관성 (p161)
- [ ] Sampling rate 통일 (16kHz 권장)
- [ ] Channel 수 통일 (Mono)
- [ ] 고정 길이 처리 방식(padding / crop / sliding window) 결정 및 **Train·Test 동일 적용**
- [ ] Crop 시 중요한 구간이 잘리지 않는지 확인 (p167)

### 평가 설계
- [ ] 클래스 불균형 확인 — Accuracy만 믿지 않기 (p53, 3차시 미니퀴즈 Q5)
- [ ] M3는 Macro F1이므로 **클래스별 F1을 개별로 모니터링**
- [ ] Baseline(TF-IDF/RandomForest) 성능을 먼저 기록하고 딥러닝과 비교 (p156)

## 6. 제출 요건 (문제p11–p12)

### 실행 규칙 — 반드시 아래 한 줄로 완결되어야 함
```bash
python inference.py --audio_dir {wav folder} --label_dir {json folder} --ckpt_path {checkpoint file} --output ./outputs/mission{미션번호}.csv
```
내부적으로 전처리·특징추출·추론·후처리를 여러 단계로 하더라도 **최종 실행은 이 명령 1회**로 끝나야 한다.

### 출력 CSV 형식
| 미션 | 컬럼 |
|---|---|
| Mission 1 | `[audio file name], [gender]` |
| Mission 2 | `[audio file name], [startAt], [endAt], [speaker]` |
| Mission 3 | `[label file name], [symptom]` |

### 제출 파일 목록
- [ ] `inference.py` (위 실행 규칙 충족)
- [ ] 학습 코드 파일 — **학습 로그가 포함된 `.ipynb`**
- [ ] 학습 완료 모델 가중치 (`.pt` / `.pth` / `.ckpt`)
- [ ] 모델 코드 파일 (`.py`)
- [ ] `requirements.txt`
- [ ] **결과 정리 PPT** — 데이터 분석 내용, 모델 설명, 결과 분석, **사회안전 시사점** 포함
- [ ] 코드 내 불필요 부분 삭제, **주석 필수**

> PPT의 "데이터 분석 내용"은 교안 2차시(EDA·분포·왜도/첨도·결측치·이상치)를 그대로 적용할 수 있는 항목이다. 발화 길이 분포, 성별/화자 클래스 비율, 증상 클래스 빈도 분포를 시각화해두면 그대로 슬라이드가 된다.
