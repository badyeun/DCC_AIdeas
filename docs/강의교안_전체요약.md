## 1차시 — AI 개요와 정보의 데이터화 (p2–p26)

### AI 파이프라인 5단계 (p3)
`문제 정의 → 데이터 수집 → 데이터 전처리 → 모델 학습 → 평가 및 배포`
이번 캠프는 **앞 세 단계(문제 정의·수집·전처리)에 집중**한다고 명시됨.

**① 문제 정의 (p4, p9)**
- 좋은 정의의 조건: 측정 가능한 목표(KPI), 데이터와 연결 가능, 비즈니스 임팩트 명확, 성공 기준이 수치
- 나쁜 예: "AI로 고객 만족도를 높이고 싶다"
- 좋은 예: "최근 3개월 구매 이력 기반으로 이탈 가능 고객을 예측해 이탈률을 15% 줄인다"

**② 데이터 수집 (p5)**
- 소스: 내부 데이터(DB/로그/CRM) · 공공 데이터(AI HUB, 공공데이터포털) · 웹 크롤링(BeautifulSoup, Selenium) · 직접 라벨링
- 체크포인트: 충분한 양 / 편향(Bias) / 라벨 유무 / 개인정보·저작권
- **Garbage In, Garbage Out** — 모델 품질은 데이터 품질을 넘을 수 없음

**③ 데이터 전처리 (p6)** — 실무 시간의 60~80% 차지
1. 결측치 처리 (평균·중앙값 대체, 행 제거)
2. 이상치 제거 (IQR, Z-Score)
3. 인코딩 (One-Hot, Label)
4. 정규화/표준화 (MinMax, StandardScaler)
5. 피처 선택
- **전처리 황금 원칙**: Train으로만 `fit()`, Val/Test는 `transform()`만. **데이터 누수(Leakage) 절대 금지**

**④ 모델 학습 (p7)**
- 지도학습(분류: 로지스틱회귀/RF/XGBoost/NN, 회귀: 선형회귀/SVR/DL), 비지도학습(K-Means, DBSCAN, PCA, t-SNE), 딥러닝(CNN/RNN·LSTM/Transformer)
- 핵심 개념: 손실 함수, 경사 하강법, 에포크, 배치, 학습률
- 과적합 → 드롭아웃·정규화 / 과소적합 → 모델 복잡도 증가

**⑤ 평가 및 배포 (p8)**
- 지표: Accuracy, Precision/Recall, F1, AUC-ROC
- 배포: REST API(Flask/FastAPI), 클라우드(SageMaker/Vertex/Azure ML), 엣지(TFLite/ONNX), 배치
- 배포 후: 데이터 드리프트 감지 → 재학습 주기 설정, A/B 테스트

### AI 역사 (p12–p15)
- **1950s**: 튜링 테스트(1950), 다트머스 회의(1956, "AI" 용어 첫 사용), Logic Theorist
- **1960–70s**: ELIZA(1966), SHAKEY(1969), 퍼셉트론 XOR 한계 증명(Minsky & Papert, 1969) → **1차 AI 겨울(1974~80)**
- **1980s**: 전문가 시스템(IF-THEN) — XCON, MYCIN → **2차 AI 겨울(1987~93)**
- **1997**: 딥블루 vs 카스파로프 3.5:2.5
- **2012**: AlexNet, ImageNet 오류율 26%→15.3%, GPU 병렬 연산 / 딥러닝 3인방(힌튼·르쿤·벤지오)
- **2016–17**: 알파고 4:1, AlphaGo Zero, **Transformer(2017, "Attention is All You Need")**
- **2018–21**: BERT(2018), GPT-2(2019), GPT-3(1,750억 파라미터, 2020), DALL-E·Codex(2021)
- **2022–**: ChatGPT(2022.11, 2개월 1억 명), GPT-4(2023), Gemini/Claude/LLaMA, 생성형 AI 대중화

### 기업 적용 사례 (p16–p17)
- **Netflix**: 시청의 80%가 추천에서 발생. 후보 생성 → 딥러닝 랭킹 → 다양성 재랭킹
- **Google**: 프로덕션 ML에서 **모델 코드는 5%**, 95%는 파이프라인·피처스토어·서빙·모니터링
- 국내: LG 챗엑사원(EXAONE 4.0), 롯데쇼핑 Tech Assistant(Amazon Bedrock), 한샘 AI 상담(해결률 48%→86%)

### 정보의 데이터화 (p19–p26)
- AI 모델은 **숫자 행렬만 입력으로 받음**. 모든 데이터는 벡터 → 행렬
- **음성 → 숫자 (p21)**: 아날로그 음성 → 샘플링&양자화(44.1kHz, 16bit) → PCM 이진 데이터(.wav) → 파형 시각화
  - 활용: 파형 → 푸리에 변환 → 스펙트럼 → **스펙트로그램(2D 이미지)** → CNN/RNN 입력
- **텍스트 → 숫자 (p22)**: 원시 텍스트 → 토크나이징 → 정수 인코딩(Vocab) → 임베딩 벡터(밀집 벡터)
- **GAN (p25–p26)**: 생성자 vs 판별자 경쟁 학습. Epoch가 늘수록 노이즈 → 윤곽 → 얼굴 특징 → 고품질 이미지

### 확률 분포 (p31–p37)

**연속형**

| 분포 | 파라미터 | AI 활용 |
|---|---|---|
| 정규분포 | μ, σ | 가중치 초기화(Xavier/He), 잔차 확인, 가우시안 노이즈 증강 |
| 균등분포 | a, b | 난수 생성, 하이퍼파라미터 Random Search, 드롭아웃 마스크 |
| 지수분포 | λ (평균 1/λ, 무기억성) | 서버 요청 간격, 생존 분석, 이상 탐지 |
| 베타분포 | α, β (0~1 확률 자체) | 베이지안 사전분포, A/B 테스트 전환율 |

**이산형**

| 분포 | 파라미터 | AI 활용 |
|---|---|---|
| 이항분포 | n, p (평균 np) | 이진 분류 확률, 오버샘플링 |
| 포아송분포 | λ (**평균=분산=λ**) | 카운트 데이터, 이상 탐지, 단어 빈도 |
| 기하분포 | p (평균 1/p, 무기억성) | 첫 이상 탐지까지 시간, RL 에피소드 길이 |
| 음이항분포 | r, p (분산>평균, 과산포) | 과산포 카운트, 단어 빈도, 재입원 횟수 |

- 68-95-99.7 규칙: ±1σ 68%, ±2σ 95%, ±3σ 99.7%

### 왜도 & 첨도 (p36, p38)
- **왜도(Skewness)**: 0=대칭, >0=오른쪽 꼬리(소득·자산), <0=왼쪽 꼬리(시험 점수)
- **첨도(Kurtosis)**: =3 정규분포, >3 Leptokurtic(뾰족, 이상치 多, 금융 수익률), <3 Platykurtic(납작)
- 실전 기준:
  - `|왜도| < 0.5` → 변환 불필요, StandardScaler 바로 적용
  - `0.5 ≤ |왜도| < 1` → `np.log1p(x)` 로그 변환
  - `|왜도| ≥ 1` → Box-Cox / Yeo-Johnson, 또는 이상치 제거 선행
  - `첨도 > 5` → IQR/Z-Score 즉시 수행 / `왜도 > 2` → 박스플롯 확인
- 모델별 민감도: 선형·로지스틱(정규분포 선호), 신경망(정규화 필수, 왜도 크면 Gradient Exploding 위험), 트리 계열(강건), 나이브 베이즈(왜도 높으면 급락)

### 시각화 (p39–p42)
- **Matplotlib**: 기반 라이브러리, 세밀한 커스터마이징
- **Seaborn**: 통계 시각화 특화, EDA·분포 확인에 적합 ← 캠프 실습 중심
- **Plotly**: 인터랙티브, 대시보드용

### 결측치 처리 (p43)
1. 탐지: `df.isnull().sum()` — 5% 미만이면 단순 처리
2. 제거: 결측 비율 **>50%인 컬럼은 삭제**
3. 대체: 수치형=평균/중앙값, 범주형=최빈값, 고급=KNN/MICE
4. 모델 기반: `is_null_flag` 새 피처 생성 (결측 패턴 자체가 의미 있을 때)

### 이상치 (p44–p45)
- **IQR**: `Q1 − 1.5×IQR` 미만 또는 `Q3 + 1.5×IQR` 초과
- **Z-Score**: `|z| > 3`
- 처리 안 할 때: 평균·분산 왜곡, 선형 모델 성능 급락, MinMaxScaler 스케일 오염
- **이상치가 오히려 핵심인 경우**: 금융 사기 탐지, 의료 이상 탐지, 제조 불량 감지 → **제거 금지, 별도 레이블링**
- 전략: 입력 오류 → 제거/결측 처리 / 극단값이지만 실제 데이터 → IQR 클리핑 / 분석 목표가 이상치 → 제거 금지

## 3차시 — 평가지표 · 경사하강법 · 퍼셉트론 (p46–p78)

### 문제 유형별 평가지표 (p48)
- 분류: 정확도, 정밀도, 재현율(민감도), 특이도, F1, ROC-AUC, Log Loss
- 회귀: MAE, MSE, RMSE, MSLE, RMSLE, R²
- 군집: ARI, NMI, 실루엣 계수
- 차원축소: 특별한 평가지표 없음

### 혼동 행렬 (p49–p58)

|  | 예측 Negative(0) | 예측 Positive(1) |
|---|---|---|
| **실제 Negative(0)** | TN | **FP — Type I error** |
| **실제 Positive(1)** | **FN — Type II error** | TP |

- **Accuracy** = `(TP+TN)/(TP+TN+FP+FN)` — 불균형 데이터에 취약 (남 90%/여 10%면 전부 남성 예측해도 90%)
- **Recall(재현율·민감도)** = `TP/(TP+FN)` — **Type II error가 중요할 때** (암 환자를 놓치면 안 되는 경우)
- **Precision(정밀도)** = `TP/(TP+FP)` — **Type I error가 중요할 때**
- **F1** = `2 × (P×R)/(P+R)` — 조화평균. Recall 1, Precision 0.01이면 산술평균 0.505지만 조화평균은 **0.019**
- **Threshold (p56)**: 0/1을 나누는 기준. 임계값을 올리면 Precision↑ Recall↓ (트레이드오프)
- **ROC-AUC (p59)**: TPR vs FPR 곡선 아래 면적. 넓을수록 좋은 모델 (전부 Positive 예측 = 우상단, 전부 Negative = 좌하단)
- **회귀 (p60)**: MAE = 오차 절댓값 평균 / MSE = 제곱 평균, 큰 오차를 강조, **MAE보다 이상치에 민감**

### 비용함수와 최적화 (p62–p68)
- 비용함수 = 설계자의 의도를 기계에 전달하는 수단. 회귀 대표 = **MSE**
- `cost(W,b) = (1/N) Σ (y − prediction(x))²`
- 최소화 방법 2가지:
  - **해석적 방법**: 정규방정식 `θ̂ = (XᵀX)⁻¹XᵀY` — 비용함수가 Convex라 전역 최솟값 1개. 단 변수가 많으면 역행렬 계산이 매우 무거움
  - **경사하강법**: 기울기 따라 점진 이동 → **변수가 많을 땐 표준**
- **Learning Rate (α)**: 한 걸음의 보폭. 대표적 하이퍼파라미터, 설계자가 정함

### 퍼셉트론과 활성화 함수 (p69–p78)
- 단층 퍼셉트론 = 선형 결합 → **XOR 분류 불가** (p70)
- 활성화 함수가 필요한 이유: 선형만 쌓으면 `y=ax → y=bx → y=cx` 는 결국 `y=abc·x` 로 선형 (p71)
- **다층 퍼셉트론 = 시점(정의역) 변환** — 층을 넘을 때 축이 바뀌어 비선형 표현 가능 (p72–p73)
- 활성화 함수 계보:
  - **Sigmoid**: 출력 0~1. 단점 ① Non-zero centered ② **Gradient Vanishing**(미분 최대 0.25)
  - **tanh**: zero-centered 해결, 기울기 최대 1. 여전히 Gradient Vanishing 존재
  - **ReLU** `max(0,x)`: Gradient Vanishing 해결, 현재 가장 널리 사용. 단점 = 음수 입력이 전부 0으로 수렴 (Dying ReLU)
  - **Leaky ReLU** `max(0.1x, x)`, **ELU** `x≥0이면 x, x<0이면 α(eˣ−1)`, **Maxout** (p78)

## 4차시 — 오차역전파 · 옵티마이저 · 초기화 (p79–p101)

### 오차역전파 (p79–p90)
- 흐름: **순전파(Feed-Forward) → 손실 계산 → 역전파 → 가중치 업데이트**, 에포크마다 반복
- 표기: `aⁿᵢ` (위첨자=층, 아래첨자=노드), `zᴸ = wᴸaᴸ⁻¹ + bᴸ`, `aᴸ = σ(zᴸ)`
- 핵심 **연쇄법칙(Chain Rule)**:
  ```
  ∂C₀/∂Wᴸ = (∂zᴸ/∂Wᴸ) × (∂aᴸ/∂zᴸ) × (∂C₀/∂aᴸ)
          = aᴸ⁻¹ × σ′(zᴸ) × 2(aᴸ − y)
  ```
- 이 과정을 출력층부터 입력층까지 반복 → 모든 가중치의 "연결의 세기"(Gradient Vector) 확보
- 출력층은 **Softmax** `exp(tᵢ)/Σexp(tⱼ)` 를 거쳐 각 클래스 확률로 변환 (p89)

### 옵티마이저 계보 (p91–p93)
```
GD ──스텝 방향──> Momentum ──> NAG ──> Nadam
 │                    │                  ↑
SGD ─스텝 사이즈─> Adagrad ─> RMSProp ─> Adam
                       └──> AdaDelta
```
- **SGD**: 전체 배치가 아닌 미니배치 사용 → 속도↑. 단점: 학습 효율 감소, 극소점 수렴 가능, 안장점에서 수렴 속도 저하
  `W(t+1) = W(t) − α·∂Cost/∂w`
- **Momentum**: 관성 추가, 진동 횟수 감소, 기울기 0에서도 멈추지 않아 **극솟값이 아닌 최솟값 수렴 가능**
  `V(t) = m·V(t−1) − α·∂Cost/∂w` , `W(t+1) = W(t) + V(t)`
- **Adagrad**: 많이 간 방향은 보폭을 줄여 세밀 탐색 / **RMSProp**: 이전 맥락을 반영해 보폭 조절
- **AdaDelta**: 보폭이 너무 작아져 정지하는 문제 완화
- **Adam** = RMSProp + Momentum (방향도 스텝 사이즈도 적절히) / **Nadam** = Adam + NAG

### 가중치 초기화 (p94–p96)
- 모든 가중치가 동일하면 학습 효율이 급락 → 랜덤 초기화 필요
- 초기값 위치가 극솟값/최솟값 수렴 여부를 좌우
- **Xavier 초기화**: `Var(W) = √(2/(n_in + n_out))` — **Sigmoid, tanh**와 짝
- **He 초기화**: `Var(W) = √(2/n_in)` — **ReLU 계열**과 짝

### 미니퀴즈 정답 요약 (p98–p101)
- 1차시: ② 문제정의→수집→전처리→학습→배포 / ② 임베딩 / ③ AI⊃ML⊃DL / ③ GAN
- 2차시: ② 중앙값 / ③ 포아송분포 / ③ 로그·Box-Cox 변환 / ③ Q1−1.5IQR 미만·Q3+1.5IQR 초과 / ③ 컬럼 삭제
- 3차시: ③ 재현율 / ② Type II 오류(FN) / ④ XOR / ③ 학습률 / ① 정확도
- 4차시: ③ ReLU / ② Gradient Vanishing / ③ 연쇄법칙 / ② Momentum / ③ He 초기화

## 5차시 — CNN과 ResNet (p102–p139)

### 컴퓨터 비전 주요 과제 (p104–p107)
이미지 분류 / 이미지 분할(Segmentation) / 객체 탐지(Detection)

### 이미지 데이터 처리 (p108–p113)
- 파이프라인: **데이터 입력(텐서화) → 전처리(Resize, Normalization) → 특징 추출(CNN, ResNet)**
- 이미지는 `(H, W, C)` 텐서. RGB = H×W 2차원 텐서 3개(3채널), 각 픽셀 0~255
- 학습 안정성을 위해 픽셀값 0~1 스케일링 (PyTorch tensor 변환 시 자동)

### CNN 구조 (p114–p129)
```
Input → [Convolution → Pooling] × N → Flatten → Fully Connected → Output
        └────── Feature Extraction ──────┘      └── Classification ──┘
```
- **왜 CNN인가**: MLP는 픽셀을 Flatten해서 **형상 정보가 소실**됨. CNN은 지역 정보(Region Feature)를 입력으로 써서 **형상 정보 보존**
- **Convolution Layer**: Filter(=Kernel, 보통 3×3·4×4)를 이동시키며 대응 원소끼리 곱해 총합 계산
- **Stride**: 필터 이동 간격 / **Padding**: 주변을 0 등으로 채워 출력 크기 조정 (Zero Padding, Full Padding)
- **Pooling Layer**: 가로·세로 Dimension 축소 (Max / Average). **학습 파라미터 없음**, 채널 수 불변, 정보 손실 존재
- **Fully Connected Layer**: Flatten 후 MLP 구조로 최종 분류

### MLP vs CNN (p138)
| 항목 | MLP | CNN |
|---|---|---|
| 입력 형태 | 1D 벡터(flatten 필요) | 2D/3D 이미지 그대로 |
| 연결 방식 | 모든 뉴런 전결합 | 지역 연결(Local) |
| 가중치 | 위치마다 다름 | **필터 공유(Weight Sharing)** |
| 공간 정보 | 소실 | 보존 |
| 파라미터 수 | 매우 많음 | 상대적으로 적음 |
| 위치 변화 | 취약 | 강건(불변성) |

### ResNet (p130–p137)
- 문제: Plain network를 깊게 쌓으면 **오히려 성능이 떨어짐** (Training에서도 저하 → 단순 Overfitting이 아님)
- 원인: 기울기 소실, Input 정보 손실, Information flow 단절
- **해결: Shortcut Connection** — 레이어 결과에 입력 x를 더함
  - Residual Block: `y = F(x, Wᵢ) + Wₛx` (Wₛ는 크기 맞추는 행렬)
  - `H′(x) = F′(x) + 1` → **기울기가 최소 1 유지 → Gradient Vanishing 해소**
  - Idea: 최적값이 Identity mapping일 때 H(x)를 맞추기보다 **F(x)=0을 맞추는 것이 쉬움**
- 구조: 전부 3×3 Conv, 점선 화살표에서 특성맵 크기 절반 + 채널 2배
- **Bottleneck (50층 이상)**: 1×1 Conv로 연산량 축소 → 152층까지 확장. **VGG-16 연산량 > ResNet-152 연산량** (x를 더하는 건 추가 파라미터가 없기 때문)

### 미니퀴즈 (p139, OX)
1. 입력 채널 수와 상관없이 필터별 1개 피처맵 생성 → **O**
2. Pooling은 학습 대상 파라미터가 없음 → **O**
3. Pooling 통과 시 행렬 크기 감소 → **O**
4. Pooling 통과 시 채널 수 불변 → **O**

## 6차시 — 텍스트 데이터와 NLP 기초 (p140–p157)

### 왜 어려운가 (p142–p144)
- 문장마다 길이가 다름 / 단어 종류가 매우 많음 / 같은 단어가 다른 의미(bank, fire) / **순서가 중요**(dog bites man vs man bites dog) / 잡음(URL, 해시태그, 이모지, 오탈자)
- 예: "The forest is on fire"(재난 O) vs "This new song is fire"(재난 X) → **문맥까지 고려해야 함**

### 텍스트 전처리 (p145–p147)
- 소문자 변환 / 불용어 제거 / **어간 추출(Stemming)**: 단순히 어미를 자름 / **표제어 추출(Lemmatization)**: 문법적 특성을 고려해 원형 복원
- 텍스트 정규화: 동의어 통합(don't ↔ do not), 오탈자 교정(teh → the), 줄임말 확장(ASAP), 숫자 통일
- **전처리를 많이 한다고 무조건 좋은 것은 아님. 목적에 따라 선택**

### 토큰화와 Vocabulary (p148–p150)
- 토큰화: "산불이 확산되었다" → 공백 기준 `["산불이","확산되었다"]` / 형태소·Subword 기준 `["산불","이","확산","되","었다"]`
- **Vocabulary**: 토큰을 숫자로 바꾸는 사전. `<PAD>`(길이 맞춤), `<UNK>`(사전에 없는 토큰)
- **Token ID는 중요도가 아니라 단순 식별 번호** (ID 100이 ID 10보다 10배 중요한 것 아님)
- **Padding + Attention Mask**: 길이가 다른 문장을 하나의 Batch로 묶기 위해 짧은 문장에 0 패딩, 긴 문장은 자름. Attention mask는 `1=실제 토큰, 0=패딩`

### 벡터화 방법 (p151–p152)
- **TF-IDF**: 특정 단어가 특정 문서에서 얼마나 중요한지를 나타내는 통계 수치
  - TF = 한 문서 안 등장 횟수 / IDF = 전체 문서에서의 희귀도
  - **Vocabulary와 IDF는 Train 데이터에서만 학습** (그 외에는 정답지를 보고 문제를 푸는 것 = 데이터 누수)
- **임베딩(Embedding)**: 단어를 의미 공간의 좌표로 표현. TF-IDF는 비슷한 단어를 연결하지 못하는 한계 → 임베딩은 fire·wildfire·smoke가 벡터 공간에서 가까이 위치

### 모델 계보 (p153–p156)
| 모델 | 특징 | 한계/비고 |
|---|---|---|
| **RNN** | 앞에서 읽은 정보를 Hidden State에 순서대로 저장 | 기울기 손실 → 앞부분을 잘 기억 못함 |
| **LSTM** | Forget/Input/Output **Gate**로 기억·제거 조절 | RNN의 장기 의존성 개선 |
| **Transformer** | 문장 전체의 관계를 **동시에** 봄. Encoder/Decoder, **Attention**(query·key로 value 가중합) | 어떤 정보가 중요한지 표현 |
| **BERT** | unlabeled text에서 **양방향 문맥** representation 사전학습 → fine-tune | 적은 데이터로도 다양한 downstream task 수행 |

**6주차 핵심 3줄 (p156)**
1. 모델은 원문을 직접 읽지 않고 숫자 표현을 입력받는다
2. TF-IDF의 Vocabulary와 IDF는 Train 데이터에서만 학습한다
3. 복잡한 모델을 쓰기 전에 **간단한 Baseline을 먼저 구축**한다

- 모델 선택 기준: TF-IDF는 단순·빠르고 어떤 단어가 영향을 줬는지 해석하기 쉬워 **Baseline으로 유용**. LSTM·BERT는 순서와 문맥 처리는 낫지만 학습 시간이 길고 해석이 복잡

### 미니퀴즈 (p157) — 정답 ②
데이터를 Train/Validation으로 **먼저 나눈 후**, Train으로 TF-IDF Vectorizer를 학습하고 Validation에는 `transform`만 적용
- 오답 포인트: 전체 데이터로 먼저 학습 = 데이터 누수 / Token ID는 중요도가 아님 / Bigram이 전체 문맥을 이해하는 것은 아니며 Validation은 여전히 필요

## 7차시 — 오디오 데이터 이해와 특징 추출 (p158–p174)

> **"모델은 소리를 듣지 못한다. 숫자로 바꿔서 인식한다."**

### 전체 파이프라인 (p161)
```
[전처리]  소리→숫자 변환 → 같은 시간 길이를 같은 sample 수로 → Channel 수 일관화 → Batch 구성
[특징추출] 시간·주파수 패턴으로 변환 (Spectrogram 계열)
```

### 소리 → 숫자 (p162–p165)
- **Sampling**: 시간축을 일정 간격으로 측정 / **Quantization**: 측정된 진폭을 일정한 숫자 단계로 표현
- **Waveform**: 진폭을 순서대로 저장한 **1차원 시계열**. 가로=시간, 세로=진폭(Amplitude)
- **주파수**: `f = 1/T`. 1초에 100번 진동 = 100Hz
- **Sampling rate** = **1초당 측정 횟수** (전체 sample 수가 아님). Duration = 총 시간
  - `Sample 수 = Sampling rate × Duration` → 16kHz 2초 = **32,000 samples**
  - Sampling rate가 높다고 항상 성능이 좋아지진 않음 (주파수 범위·모델·계산 자원 고려)
- **Mono / Stereo**: Stereo는 두 신호 간 진폭차·도착시간차·위상차 → 소리의 방향과 공간감 정보

### 길이 맞추기 전처리 (p166–p168)
Batch를 만들려면 동일 크기 Tensor가 필요 → 세 가지 기법
- **Padding**: 짧은 오디오를 겹치지 않는 값으로 늘림
- **Crop**: 긴 오디오에서 일부 구간만 선택. **위험: 중요한 소리를 제거할 수 있음**
- **Sliding window**: 긴 오디오를 일정 길이의 여러 구간으로 분할

### Frame / Window / Hop length (p169)
- 오디오는 시간에 따라 주파수 특성이 변하므로 짧은 Frame으로 나눠 각각의 주파수를 계산
- **시간-주파수 해상도 Trade-off**
  - Window 짧음 → 시간 변화를 세밀히 관찰 가능, 주파수 구분은 어려움
  - Window 길음 → 가까운 주파수 구분 우수, 시간 해상도 저하

### 주파수 변환 (p170–p173)
- **Fourier Transform**: 복잡한 신호를 여러 단순 주파수 성분으로 분해. **단, 시간 정보가 사라짐**
- **STFT (Short-Time Fourier Transform)**: 짧은 Frame으로 나눠 각 Frame에 FT 적용 → **시간과 주파수를 동시에 표현**
- **Spectrogram**: 가로=Time frame, 세로=Frequency, 색/밝기=Magnitude(Power). **2차원 이미지**
- **Mel-spectrogram**: 주파수를 인간 청각에 맞춘 **비선형 멜 척도**로 변환. 저주파(약 20~500Hz)는 세밀한 해상도, 고주파는 넓은 간격
- **MFCC (Mel-Frequency Cepstral Coefficients)**: Mel spectrogram에 **DCT**를 적용해 더 압축한 계수. 음성 인식에서 매우 유용
  - Mel(청각 특성) + Frequency(주파수) + Cepstral(log spectrum 재변환) + Coefficient(계수)

### 미니퀴즈 (p174)
1. 16kHz 2초 오디오 → **32,000개 sample**
2. Spectrogram 가로축=**시간**, 세로축=**주파수**

## 8차시 — 오디오 딥러닝과 응용 · 멀티모달 (p175–p190)

### 오디오 딥러닝 종류 (p177)
- **Audio Classification**: 전체 파일에 하나 또는 여러 개의 Label 예측
- **Sound Event Detection**: 어떤 소리가 포함되어 있는지 + **언제 시작·종료하는지**까지 예측
- 같은 CNN이라도 정답이 하나인지 여러 개인지에 따라 **출력층과 손실함수가 달라짐**

### Audio CNN (p178–p179)
- **Log-Mel spectrogram**: 사람 귀의 인지 방식(저주파에 민감, 진폭은 로그 단위로 인식)을 **주파수축과 진폭축 모두에 반영**한 2D 표현
- 2차원 데이터이므로 **이미지와 동일하게 CNN으로 처리 가능**

### Audio 증강 (p180–p181)
동일인이 같은 단어를 말해도 녹음 장비·마이크 거리·배경 소음·공간 울림에 따라 Waveform과 Spectrogram이 달라짐. 조용한 환경만 학습하면 단어 특징뿐 아니라 **깨끗한 녹음 조건까지 함께 학습**해버림.

- **Waveform-level augmentation**: Noise 추가 등 원 파형에 대한 변형
- **Feature-level augmentation (SpecAugment 계열)**
  - **Time masking**: 일부 시간 구간 마스킹
  - **Frequency masking**: 일부 주파수 대역 마스킹
- **Noise augmentation**: 실제 배경 Noise를 원본 오디오에 추가해 다양한 녹음 환경을 모사
  - **Noise의 종류와 크기가 중요** — 적용 환경과 무관한 Noise만 쓰면 현실적 일반화 성능을 얻기 어려움
  - 산림 환경 → 바람·비·곤충·차량·센서 잡음 / 실내 음성 인식 → 에어컨·키보드·대화
  - "최대한 원본 음성을 방해하지 않는 선에서 Noise 증강 적용"
- **증강은 Training 데이터에만 적용**. Validation/Test는 고정된 전처리를 써야 일관된 평가 가능

### 사전학습 모델 (p182–p183)
| 모델 | 입력 | 방식 |
|---|---|---|
| **Wav2Vec2** (Meta, 2020) | **Raw waveform** | 정답 문장 없는 대규모 음성에서 일부 구간을 Masking하고 주변 문맥으로 복원 학습 → Fine-tuning |
| **AST** (Audio Spectrogram Transformer) | **Log-Mel spectrogram** | 시간–주파수 **Patch**로 나눠 각각을 Token처럼 Transformer에 입력. CNN 없이 Attention만 사용 |

### 멀티모달 (p184–p189)
- **모달리티(Modality)**: 우리가 세상을 인식하는 정보의 종류·형태 (시각, 청각, 텍스트 등)
- 이미지는 CNN이 Pixel로부터, 텍스트는 BERT가 Token으로부터, 오디오는 CNN이 Spectrogram으로부터 또는 Wav2Vec2가 Raw waveform으로부터 특징 생성 → **결국 모두 숫자이므로 결합 가능**
- **Fusion 전략 3가지 (p186)**
  1. **Early Fusion**: 전처리 후 입력단에서 바로 결합
  2. **Late Fusion**: 각각 독립 모델을 통과시킨 뒤 최종 예측값을 결합
  3. **Joint / Intermediate Fusion**: 각 인코더로 Feature 추출 후 **중간 레이어에서 결합** ← **가장 많이 사용**
- 응용: 의료영상 융합(CT/MRI + PET), 위성영상 융합(Pansharpening), RGB-D 융합
- 미래: 처음부터 모든 데이터를 함께 학습하는 **LMM(Large Multimodal Model)** — Gemini, GPT-4V

### 미니퀴즈 (p190) — 정답 ③
Audio augmentation은 실제 환경에서 발생할 수 있는 변화를 학습 데이터에 적용하는 방법이며, **wav2vec 2.0은 주로 Raw waveform**, **AST는 주로 Log-Mel spectrogram**을 입력으로 사용
- 오답 포인트: 주파수 영역을 가리는 것은 Frequency masking(Noise augmentation 아님) / **SNR이 높을수록 신호가 깨끗함** / 랜덤 증강은 Training에만 적용
